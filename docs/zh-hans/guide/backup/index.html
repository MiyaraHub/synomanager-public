备份真的运行了吗？

Hyper Backup

每个任务，以及它正在做什么

顶部是摘要，显示共有多少任务、多少正常、多少出现问题，下面是每个任务一张卡片。

显示内容含义
任务名称与你在 Hyper Backup 中命名的一致。
目标位置备份到哪里，比如 Synology C2、远程 NAS、本地文件夹或云服务商。
状态空闲、运行中或失败。运行中的任务会显示实时进度条。
备份大小任务在目标位置占用多少空间。
源大小它要备份多少数据。
上次备份上次运行结束于多久之前。
下次备份计划下一次何时触发。
立即运行立刻启动任务。运行中的任务可以取消。
有意显示两个数字

备份大小与源大小并排显示

大多数工具只显示其中之一。放在一起，就能回答单独一个数字回答不了的问题。

  • 去重和压缩帮你节省了多少。758 GB 的源数据在目标位置占用 814 GB，与占用 300 GB 所说明的情况大不相同，只有成对来看才能发现。
  • 目标位置是否快要写满。源数据的增长和目标位置的增长并不是同一条曲线，而对于“下个月会不会失败”这个问题，关键是目标位置。
  • 版本是否在失控增长。目标位置的增长速度远超源数据，通常意味着保留策略保留的内容比你预想的多。
Active Backup

Active Backup for Business

顶部显示设备和任务数量，接着是存储库大小，然后是各台设备。

备份大小

  • 存储库去重后的总大小，按存储空间统计。
  • 按工作负载细分，包括电脑、服务器、虚拟机和 DSM 设备，各自显示设备数量和大小。
  • 如实标注：这是 Active Backup 报告的目标位置去重后大小，而不是把源大小相加后冒充的结果。

设备

  • 每台受保护的设备，附带其地址和操作系统。
  • 上次备份，如果从未运行则显示从未，这一条才是值得留意的。
  • 每台设备都有立即备份。
出问题时

不用查看也能知道

  • 任务卡片会直接说明，并显示 NAS 上报的状态。
  • 主屏幕的健康徽章也会反映出来，所以备份失败会出现在你看到的第一个界面上，而不是点了三下之后才发现。
  • 从未备份过的设备显示为从未，而不是空白或零，因为那样看起来像是“没问题”。
应用不会做的事：创建或编辑备份任务、更改保留策略、从备份还原。这些是 Hyper Backup 自己的工作，尤其是还原，在手机上不该一不小心就开始。
常见问题

备份常见问题

能在手机上启动备份吗？
可以。每个 Hyper Backup 任务都有“立即运行”按钮，运行中的任务会显示实时进度条，并可取消。
备份大小和源大小有什么区别？
源大小是任务要备份的数据量。备份大小是它在目标位置经过去重和压缩后实际占用的空间。两者放在一起看，就能知道它们帮你节省了多少，以及目标位置的增长是否比源数据更快。
能显示 Active Backup for Business 吗？
可以，会显示按工作负载细分的去重后存储库大小，各自附带设备数量，还会列出每台受保护设备的上次备份时间和“立即备份”按钮。
备份失败时会通知我吗？
会。每个任务都会显示状态，失败的任务还会让主屏幕上的健康徽章变色。
能在应用里从备份还原吗？
不能。还原要在 Hyper Backup 或 Active Backup 中进行，版本选择器和目标选择都在那里。应用负责监控和触发备份，不负责把数据放回去。
