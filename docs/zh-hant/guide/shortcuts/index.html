捷徑 & 連結

直接前往你要的畫面

Syno Manager 註冊了 synomanager:// URL 配置，因此 Siri 語音片語、啟動器捷徑或自動化 App 都能直接把 App 開在你需要的地方，而不是首頁。在 Mac 上，Siri 與「捷徑」App 能原生辨識 Syno Manager，完全不需要輸入 URL。

刻意設下的限制

為什麼重新啟動與關機只會開啟 App

它們會帶你到電源控制畫面，本身不會重新啟動或關閉任何東西。

捷徑是可能不小心觸發的東西 - 誤點的啟動器圖示、聽錯的語音片語、在錯誤時機觸發的自動化。重新啟動 NAS 會中斷所有正在使用它的人，也會打斷它正在進行的工作。這兩件事不該湊在一起，所以連結只到畫面為止，既有的確認機制仍然適用。

其他所有連結本質上都很安全，因為它們只是顯示東西給你看。這就是為什麼其餘的都一點即達，而這兩個不是。
如何使用

各平台的做法

iOS - Siri 與捷徑

  1. 開啟捷徑並建立新的捷徑。
  2. 加入開啟 URL 動作。
  3. 輸入連結，例如 synomanager://storage。
  4. 取一個你會大聲說出口的名稱 - 「查看我的 NAS 儲存空間」。
  5. 加到主畫面，或直接問 Siri。

Android - 啟動器與自動化

  1. 大多數啟動器都能放置一個開啟 URL 的捷徑。
  2. 自動化 App - Tasker、MacroDroid 等 - 可在任何觸發條件下開啟它。
  3. 筆記或網頁中的 <a href="synomanager://system"> 連結同樣有效。
要在哪一台 NAS 上開啟，依你的啟動行為設定而定。捷徑選擇的是畫面，而不是裝置 - 所以在設定為「上次使用的 NAS」時，synomanager://storage 會顯示你上次所在那台 NAS 的儲存空間。
macOS

Siri 與捷徑的原生支援

在 Mac 上，Syno Manager 完全不需要 URL。它直接向 Apple 的 App Intents 註冊了三個動作，因此 Siri 與「捷徑」App 會把 Syno Manager 視為一個有自己詞彙的 App，就像看待 Apple 自家的 App 一樣。

動作功能對 Siri 說
開啟區段開啟 Syno Manager 並直接前往你選擇的區段 - 儀表板、儲存空間、系統、網路、App、備份、檔案或喚醒。「開啟 Syno Manager」
重新啟動 NAS先請你確認，然後開啟 App 並停在電源控制畫面。在你於該處再次確認之前，不會對 NAS 傳送任何指令。「用 Syno Manager 重新啟動我的 NAS」
關閉 NAS與重新啟動的流程相同：先透過 Siri 或捷徑確認，然後 App 開啟並停在電源控制畫面。「用 Syno Manager 關閉我的 NAS」
重新啟動與關機仍需確認兩次。Siri 或捷徑會先詢問 - 「要開啟 Syno Manager 來重新啟動 NAS 嗎？目前尚未對 NAS 傳送任何指令 - 你要在 App 中確認」 - 然後 App 本身的電源控制會再問一次。一個聽錯第一個字就讓 NAS 重新開機的語音指令，不是什麼值得擁有的功能。

你可以在這些基礎上打造自己的自動化。因為它們是一般的捷徑動作，「開啟區段」可以放進你建立的任何捷徑中 - 排程執行、由 Home Hub 觸發，或接在其他動作之後 - 與其他任何 Mac App 的動作完全一樣。

常見問題

捷徑常見問題

Syno Manager 有 URL 配置嗎？
有。synomanager://<name> 可讓 App 直接開啟特定畫面。儀表板、儲存空間、系統、網路、App、備份、檔案與喚醒各有一個。
捷徑可以一點就重新啟動我的 NAS 嗎？
不行，而且是刻意的。重新啟動與關機的連結只會開啟 App 並停在電源控制畫面，那裡仍會套用既有的確認機制。
我可以搭配 Siri 使用嗎？
可以。在 Apple 的「捷徑」App 中建立一個開啟該 URL 的捷徑，為它設定一個語音片語，Siri 就會直接帶你過去。
捷徑可以指定特定的 NAS 嗎？
不行。捷徑只會開啟一個畫面；要在哪一台 NAS 上開啟，則依你的啟動行為設定而定。
Syno Manager 能在 Mac 上搭配「捷徑」App 使用嗎？
可以，而且是原生支援。「開啟區段」、「重新啟動 NAS」與「關閉 NAS」會以 Syno Manager 動作的形式出現在 macOS 的 Apple「捷徑」App 中，不需要輸入任何 URL。兩個電源動作會先請 Siri 或捷徑確認才執行任何動作，然後只會開啟 App 並停在電源控制畫面。
