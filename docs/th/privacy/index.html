ข้อมูลไปที่ไหน
ทุกอย่างที่ NAS ของคุณรายงาน - ค่าระบบ พื้นที่จัดเก็บ เครือข่าย คอนเทนเนอร์ แพ็กเกจ บันทึก ผู้ใช้ งานตามกำหนดโทรศัพท์ไป NAS โดยตรง ไม่มีเซิร์ฟเวอร์ของเราในเส้นทาง
ไฟล์ รูปภาพ และสตรีมกล้องของคุณโทรศัพท์ไป NAS โดยตรง ผ่านเส้นทางใดก็ตามที่คุณกำหนด
ชื่อผู้ใช้ รหัสผ่าน และโทเคนอุปกรณ์ 2FA ของ DSM ของคุณkeychain หรือ keystore ของอุปกรณ์ ไม่เคยส่งไปที่ใดนอกจาก NAS ของคุณ เพื่อลงชื่อเข้าใช้
คำถามที่คุณถามผู้ช่วยและคำตอบไม่ไปที่ไหน จัดการโดยโมเดลบนอุปกรณ์
การตั้งค่าแอป - ธีม เลย์เอาต์ การสำรวจข้อมูล หน่วยอยู่บนอุปกรณ์ เว้นแต่คุณส่งออกเอง
รายงานการแครชFirebase Crashlytics สิ่งเดียวที่ออกไป ดูด้านล่าง
ไม่มีตัวกลาง

ไม่มีเซิร์ฟเวอร์ MiyaraHub คั่นระหว่างคุณกับ NAS ของคุณ

นี่เป็นเรื่องของสถาปัตยกรรม ไม่ใช่นโยบาย Syno Manager เป็นไคลเอนต์ที่ใช้ API ของ DSM เอง ซึ่งเป็นตัวเดียวกับที่เว็บอินเทอร์เฟซของ DSM เรียก โดยตรงจากโทรศัพท์ไปยัง DiskStation ของคุณ

  • บนเครือข่ายของคุณเอง การเชื่อมต่อเป็นโทรศัพท์ไป NAS ผ่าน LAN
  • ผ่าน QuickConnect ไปผ่านรีเลย์ของ Synology ซึ่งเป็นบริการของ Synology ภายใต้บัญชี Synology ของคุณ ไม่ใช่ของเรา
  • ผ่านโดเมนหรือ VPN เป็นการเชื่อมต่อตรงไปยังที่อยู่ของคุณ
  • ไม่ว่ากรณีใด ไม่มีบริการของ MiyaraHub ในเส้นทาง ไม่มีที่ให้ข้อมูลของ NAS คุณผ่าน และไม่มีที่เก็บมัน
ข้อมูลเข้าสู่ระบบ

รหัสผ่านของคุณอยู่ที่ไหน

  • ที่เก็บข้อมูลปลอดภัยของแพลตฟอร์ม Keychain บน iOS และ macOS ที่เก็บเข้ารหัสที่ใช้ Keystore บน Android ไม่เคยเป็นข้อความธรรมดา และไม่เคยอยู่ในไฟล์ค่ากำหนดทั่วไป
  • ถูกยกเว้นจากการสำรองข้อมูลของอุปกรณ์ แอปยกเว้นไฟล์ที่เก็บข้อมูลปลอดภัยจากการสำรองข้อมูลบนคลาวด์ของ Android และการโอนย้ายอุปกรณ์อย่างชัดเจน การกู้คืนหรือย้ายโทรศัพท์จึงไม่พารหัสผ่าน NAS ของคุณไปด้วย คุณกรอกใหม่หนึ่งครั้ง
  • ถูกยกเว้นจากการส่งออกการตั้งค่าของแอปเอง ไฟล์สำรองและกู้คืน &ตั้งใจไม่มีการเชื่อมต่อ รหัสผ่าน หรือเซสชัน - ไฟล์พกพาที่มีรหัสผ่าน NAS ก็คือไฟล์พกพาที่มีรหัสผ่าน NAS
  • ล้างเมื่ออ่านไม่ได้ หากถอดรหัสข้อมูลเข้าสู่ระบบที่เก็บไว้ไม่ได้ ซึ่งอาจเกิดหลังกู้คืนลงฮาร์ดแวร์ใหม่ แอปจะล้างและขอให้คุณลงชื่อเข้าใช้ แทนที่จะลองซ้ำกับสิ่งที่อ่านไม่ได้
ข้อยกเว้น

รายงานการแครช

แอปมี Firebase Crashlytics และเปิดใช้งานอยู่ เมื่อแอปแครช จะส่งรายงานวินิจฉัยเพื่อให้พบและแก้ไขการแครชได้

รายงานการแครชมีอะไร

  • stack trace - โค้ดส่วนไหนล้มเหลว และที่ไหน
  • รุ่นอุปกรณ์และเวอร์ชันระบบปฏิบัติการ
  • เวอร์ชันแอปและหมายเลขบิลด์

สิ่งที่ไม่มี

  • ที่อยู่ ชื่อ หรือการกำหนดค่าของ NAS ของคุณ
  • ชื่อผู้ใช้ รหัสผ่าน หรือโทเคน DSM ของคุณ
  • ไฟล์ รูปภาพ ภาพจากกล้อง หรือบันทึกของคุณ
  • สิ่งที่คุณถามผู้ช่วย
ทำไมจึงมีสิ่งนี้ การแครชที่ไม่มีใครเห็นคือการแครชที่ไม่ได้รับการแก้ไข การแลกเปลี่ยนคือ stack trace เพื่อให้พบบั๊ก - และระบุไว้ตรงนี้แทนที่จะซ่อน เพราะหน้าความเป็นส่วนตัวที่เงียบ ๆ ละเว้นสิ่งเดียวที่ส่งออกไปไม่ใช่หน้าความเป็นส่วนตัว
ผู้ช่วย

บังคับโดยบิลด์ ไม่ใช่คำสัญญา

ผู้ช่วยบนอุปกรณ์ใช้โมเดลที่มีอยู่แล้วบนโทรศัพท์ของคุณ คำถาม ข้อมูลของ NAS และคำตอบของคุณไม่เคยออกจากอุปกรณ์ และใช้ได้เมื่อปิดเครือข่าย

ส่วนที่ควรบอกตรง ๆ: นี่ไม่ใช่นโยบายที่ใครต้องจำ การตรวจสอบในบิลด์ของแอปล้มเหลวหากพบโฮสต์คลาวด์ SDK คลาวด์ หรือคีย์ API ที่ใดในโค้ดของผู้ช่วย การรับประกันนี้เป็นเชิงโครงสร้าง

Syno Manager ส่งข้อมูล NAS ของฉันไปที่ไหนไหม
ไม่ โทรศัพท์ของคุณเชื่อมต่อกับ NAS โดยตรง ไม่มีเซิร์ฟเวอร์ MiyaraHub ในเส้นทางนั้น ไฟล์ รูปภาพ ภาพจากกล้อง บันทึก ตัวเลขการใช้งาน และการกำหนดค่าของคุณจึงไม่เคยมาถึงเราหรือใครอื่น
มีอะไรออกจากโทรศัพท์ของฉันเลยไหม
หนึ่งอย่าง: รายงานการแครช ผ่าน Firebase Crashlytics - stack trace รุ่นอุปกรณ์ และเวอร์ชันแอป ไม่มีข้อมูลของ NAS ข้อมูลเข้าสู่ระบบ หรือไฟล์ของคุณ
ข้อมูลเข้าสู่ระบบ NAS ของฉันเก็บไว้ที่ไหน
ในที่เก็บข้อมูลปลอดภัยของแพลตฟอร์ม - Keychain บน iOS ที่เก็บที่ใช้ Keystore บน Android - ไม่เคยเป็นข้อความธรรมดา และถูกยกเว้นอย่างชัดเจนจากการสำรองข้อมูลบนคลาวด์ของ Android และการโอนย้ายอุปกรณ์
ผู้ช่วยส่งคำถามของฉันไปยังเซิร์ฟเวอร์ไหม
ไม่ ผู้ช่วยรันโมเดลที่มีอยู่แล้วบนอุปกรณ์ของคุณและใช้ได้เมื่อปิดเครือข่าย บิลด์ของแอปจะล้มเหลวหากพบโฮสต์คลาวด์ SDK หรือคีย์ API ที่ใดในผู้ช่วย
มีโฆษณาหรือตัวติดตามไหม
ไม่มีโฆษณา ไม่มีค่าสมาชิก และไม่มีการซื้อในแอปในแอปนี้
