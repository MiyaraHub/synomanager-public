为什么要换

一个应用，管理整台 NAS

Syno Manager 是一款第三方 Synology 客户端，它关注的不是“手机应用能对文件做什么”，而是“NAS 用户到底要查看什么，又想在沙发上就把什么修好”。

整体思路

用户转投的六个理由

🔢

一个应用，而不是好几个

系统、存储、网络、容器、套件、摄像头、照片、备份、文件、用户和任务，全在一处，一次连接，一次登录。

🚩

指出原因的健康徽章

不只说“警告”，而是告诉你哪块硬盘、哪个存储空间、什么温度。读不到的数据，它绝不会假装显示健康的对勾。

🔧

不只是监控，还能控制

在手机上重启容器、安装套件、运行备份、开关服务、弹出硬盘、唤醒设备、切换风扇模式。

🌐

离家在外也一样好用

照片、摄像头实时画面和文件下载都通过 QuickConnect 完成。无需端口转发，离开家功能也不打折。

🎨

属于你的仪表盘

任意卡片都可重新排序、折叠或隐藏，还能自选底部标签栏、强调色，并在 OLED 屏上使用纯黑。下次打开，仍是你离开时的样子。

✨

设备端助手

用日常语言询问你的 NAS，由手机上的模型作答。可离线使用，不向任何地方发送数据，而且只读不写。

设计准则

可能有两种含义的数字，会被明确标注，而不是靠猜

这一原则贯穿整个应用，它很难在截图里看出来，却在日常使用中最有价值。

  • 读不到的设置会标注为未读取，而不是显示为零，因为在 Download Station 中，零表示“无限制”，读取失败却显示为零，等于理直气壮地撒谎。
  • 不妄称 VPN 配置的状态，因为DSM 的记录里没有状态字段可供读取。
  • 小组件会标明数据的读取时间，否则安静的 NAS 和过期的小组件看起来毫无区别。
  • 弹出操作以硬盘确实离开为准，而不是以请求被接受为准。
  • 风扇模式变更后会回读确认，所以 NAS 拒绝的模式会如实报告为被拒绝。
  • 无法识别的状态按原样显示：既不是运行也不是关机的虚拟机，会显示 NAS 所用的原词和恢复控件，而不是一个根本无法生效的“启动”按钮。

给正确读数贴上错误的标签，看上去会和真实读数一样权威，没人看得出来。这值得比功能清单更用心。

隐私

中间没有服务器

  • 没有 MiyaraHub 服务器。你的手机直接连接你的 NAS，这条路径上没有别的东西。
  • 凭据存放在系统钥匙串中，绝不以明文保存，也不纳入设备备份。
  • 助手在设备上运行，一旦其中出现任何云端 SDK 或 API 密钥，构建就会失败。
  • 一次性 $9.99，按平台定价。无广告，无订阅，无内购。Apple 平台通用购买一次，涵盖 iPhone、iPad 和 Mac。
  • 崩溃报告是唯一的例外，而且我们明确告知，而不是藏起来。
独立运作，并坦诚相告。Syno Manager 由 MiyaraHub Technologies 开发，与 Synology 没有隶属关系。它使用 DSM 公开文档中的 API，也就是 DSM 自带网页界面所调用的那些。

隐私政策

常见问题

为何换用，答疑解惑

为什么要用第三方的 Synology 应用？
因为 Synology 把移动端功能拆分到了多个应用里，每个只做好一件事。Syno Manager 则是另一种思路：一个应用既能监控 NAS，又能在手机上控制你想控制的一切，无需在多个应用之间跳转。
它能取代 DSM 吗？
不能，也不打算取代。DSM 用来搭建，Syno Manager 用来查看和操作。
后续还要付费吗？
不用。Syno Manager 是一次性购买，$9.99，无广告、无订阅、无内购。它按平台定价，因此 Google Play 和 Microsoft Store 需分别购买；Apple 是通用购买一次，同时涵盖 iPhone、iPad 和 Mac。
第三方应用会不会不安全？
Syno Manager 直接连接你的 NAS，中间没有任何 MiyaraHub 服务器。凭据保存在设备钥匙串中，并且不会被纳入设备备份，助手的模型也运行在手机上。唯一会离开设备的是崩溃报告，其中只有堆栈跟踪，不包含任何 NAS 信息，详见隐私。
它能用在我的 NAS 上吗？
只要运行 DSM 7.0 或更高版本，就可以。详见兼容性。
